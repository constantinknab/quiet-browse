# Quiet Browse 1.0.3 — TikTok acceptance record

Constantin approved publishing the corrected local 1.0.3 build on September 13,
2026 with “ok, ship it.” The release uses the same approved extension bytes.
No individual checklist results, browser version, or signed-in state were supplied,
so the reusable checklist below is not marked complete. This approval does not
certify universal compatibility or complete the broader Web Store review gates.

## Scope

Only TikTok landing-feed behavior changes. This corrected candidate handles
language/region/script prefixes such as `/en/`, `/en-US/`, and `/zh-Hant-TW/`,
escaped language codes, and For You landing aliases. Unknown landing aliases
also work when TikTok's homepage shell or selected-home navigation plus a known
stream identifies them. Utility pages and shared items are explicitly excluded
from that inference, including when the old homepage markup remains mounted.

The controller recognizes multiple inner-stream layouts without depending on
scroll measurements or two loaded items. It mutes and pauses both video and separate audio within that stream while the
landing-feed control is effective. It also handles playback/unmute attempts and
replacement media. Turning the control off restores the previous mute state,
but never starts playback automatically.

Direct videos, messages, and profiles remain usable, including localized links.
Following's feed adapter, other social controls, YouTube, shopping, paging,
grayscale, and the adult filter are unchanged.
Version metadata is 1.0.3. Existing saved opt-outs and schedules are preserved.

## Automated evidence

- The 62 TikTok fixture checks passed in isolated headless Chrome.
- The same checks passed with media autoplay allowed in a disposable test
  profile, so the fixture does not rely only on Chrome denying autoplay.
- Both social-route tests passed, including the `/en/` regression that failed
  before this correction and localized direct-item/message safeguards.
- Only changed source and fixture files receive syntax/format checks.
- The extension-only ZIP is checked against the exact extension source bytes.

The live `/en/` layout was also inspected: it uses the recognized
`main-content-homepage_hot` shell and `column-list-container` stream.
This inspection is not a live end-to-end extension test. No implementation can
guarantee compatibility with every future TikTok layout; repeat the checks
when layouts change or before publishing another candidate.

## Install the candidate

1. Save unfinished work before refreshing TikTok.
2. Open `chrome://extensions` in desktop Chrome (or `brave://extensions` in Brave).
3. Temporarily disable the Web Store copy of Quiet Browse if it is installed, so
   two copies do not interfere. Do not uninstall it or clear its saved data.
4. The existing `dist/quiet-browse-1.0.3-test/` folder has been refreshed with
   the corrected source. If you already loaded that folder (or `extension/`),
   click **Reload** on its extension card. There is no need to uninstall again.
   Otherwise, turn on Developer mode, click **Load unpacked**, and select that
   test folder in this repository. This has its own settings; check that
   **Hide TikTok landing feed** is on and not outside a scheduled window.
5. Confirm the extension card shows **1.0.3**, then reload existing TikTok tabs
   or open a fresh one. Reloading the extension alone leaves old page scripts
   invalidated until the TikTok page is reloaded too.

## Reusable live test

Record your browser version, OS, and whether you are signed in.

- [ ] First open `https://www.tiktok.com/en/`, the URL from the failing screenshot.
  There is no visible For You scrolling stream and no feed audio.
- [ ] Repeat on `https://www.tiktok.com/`, your usual bookmark/search link,
  and another language/region landing link you use. Record the final URL after
  any redirect. The stream stays hidden and silent on each landing page.
- [ ] Keep the tab open for 30 seconds, try wheel/trackpad scrolling, and reload
  it twice. The stream does not reappear and sound does not start.
- [ ] Search and navigation remain available. Open a profile, Messages if signed
  in, and a directly shared `/@user/video/id` link. A direct video's normal sound
  control works. Return to `/en/`; the hidden feed is silent again.
- [ ] Uncheck **Hide TikTok landing feed**. The feed returns. Start playback
  yourself and test sound. Recheck it while playback is active: the inner feed
  hides and its sound stops. Repeat this twice.
- [ ] Turn off Quiet Browse for TikTok. The page is usable and media can play
  normally. Turn it on again: the default-selected landing control hides and
  silences the stream. Reload while off and while on.
- [ ] If you use schedules, set the landing control to a window outside the
  current time: the feed/audio controls return. Switch it to always on: the
  stream hides and is silent again. Do not change the other social schedules.
- [ ] Check `chrome://extensions` → this test copy → **Errors**. Record any
  service-worker/content-script errors, and send a screenshot if the feed or
  sound still leaks.
